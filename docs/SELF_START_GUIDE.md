# Self Start Guide: как самостоятельно делать fullstack-проекты

Этот документ сделан как практичная карта: от установки инструментов до деплоя и роста в уровне.

## 1. Базовый набор программ

### Обязательный минимум

1. `VS Code`
2. `Node.js 20 LTS`
3. `Git`
4. `Docker Desktop`
5. `Postman` или `Insomnia`

### Полезные программы

1. `DBeaver` или `TablePlus` для работы с БД.
2. `GitHub Desktop` (если пока тяжело с git в терминале).
3. `Notion`/`Obsidian` для задач и заметок.
4. `Figma` для быстрых wireframe.

### Рекомендуемые VS Code Extensions

1. ESLint
2. Prettier
3. EditorConfig
4. GitLens
5. Error Lens
6. Docker
7. REST Client

## 2. Режим работы solo-разработчика

### Ежедневный цикл (1-2 часа в день тоже достаточно)

1. Открыть `roadmap` и выбрать 1 микро-фичу.
2. Создать ветку `feature/<name>`.
3. Реализовать backend часть.
4. Реализовать frontend часть.
5. Проверить вручную + тест запросов в Postman.
6. Сделать коммит.
7. Коротко записать результат в `CHANGELOG.md`/README.

Главный принцип: лучше 30-60 минут стабильного прогресса каждый день, чем редкие марафоны.

## 3. Как разбивать задачу, чтобы не застрять

Пример фичи: "Добавить поиск по лидам"

1. Backend:
   - добавить query-параметр `search`;
   - поправить SQL.
2. Frontend:
   - input для поиска;
   - запрос с debounce.
3. QA:
   - пустой поиск;
   - поиск спецсимволов;
   - длинный текст;
   - отсутствие результатов.
4. Docs:
   - обновить README (1-2 строки).

Если задача кажется большой, режьте дальше до задач на 30-90 минут.

## 4. Git-практика для начинающего

### Минимальные команды

```powershell
git checkout -b feature/add-search
git status
git add .
git commit -m "feat: add leads search endpoint and UI input"
git push -u origin feature/add-search
```

### Формат коммитов

1. `feat:` новая функциональность
2. `fix:` исправление бага
3. `refactor:` улучшение структуры без изменения поведения
4. `docs:` документация
5. `chore:` сервисные изменения

## 5. Как тестировать без сложной инфраструктуры

### Минимальный уровень

1. Ручная проверка happy-path.
2. Проверка 3-5 негативных кейсов.
3. Postman-коллекция по основным роутам.

### Что добавить дальше

1. Backend unit tests (vitest/jest).
2. API integration tests (supertest).
3. Frontend component tests (testing-library).
4. E2E (Playwright/Cypress).

## 6. Как писать код быстрее и чище

1. Перед кодом: 5 минут на псевдоплан.
2. Двигаться от API-контракта:
   - сначала schema/route;
   - потом UI.
3. Не делать крупные PR: 1 PR = 1 смысл.
4. Каждые 45-60 минут запускать локальную проверку.
5. Документация сразу после фичи, не "потом".

## 7. Как создать свой проект с нуля (шаблон)

### Шаг 1: выбрать домен

Выберите тему, где есть реальные сущности и процесс. Примеры:
1. CRM для лидов
2. Трекер привычек
3. Финансовый трекер
4. Система задач команды

### Шаг 2: описать MVP одним абзацем

Шаблон:
"Пользователь может зарегистрироваться, создать сущность X, видеть список X, менять статус X."

### Шаг 3: определить сущности

Для каждой сущности:
1. Поля
2. Валидация
3. Связи
4. CRUD-операции

### Шаг 4: сделать backend skeleton

1. `health` endpoint
2. `auth` endpoint
3. 1 бизнес-сущность CRUD
4. защита JWT
5. базовая валидация

### Шаг 5: сделать frontend skeleton

1. экран логина/регистрации
2. dashboard layout
3. форма создания записи
4. список/таблица записей
5. уведомления об ошибках

### Шаг 6: сделать production-базу

1. docker-compose для локальной БД
2. .env.example
3. скрипты запуска
4. README с "как запустить за 5 минут"

### Шаг 7: публикация в портфолио

1. 3 скриншота
2. ссылка на live demo
3. ссылка на GitHub
4. кратко: проблема, решение, стек, результат

## 8. Путь роста на 3 месяца

### Месяц 1

1. 1 MVP-проект (как этот)
2. Основы SQL и индексов
3. Auth + роли + базовый деплой

### Месяц 2

1. Тесты и обработка ошибок
2. Кэширование (Redis)
3. Очереди задач (BullMQ/RabbitMQ)

### Месяц 3

1. Микросервисный модуль (1 сервис отдельно)
2. CI/CD пайплайн
3. Наблюдаемость (логи, метрики, алерты)

## 9. Практичный чеклист перед каждым релизом

1. `npm run dev` запускается без ошибок.
2. Авторизация работает.
3. Бизнес-флоу проходит end-to-end.
4. Ошибки API читаемы для UI.
5. README актуален.
6. Есть план следующего улучшения.

## 10. Что делать, если "не понимаю, с чего начать"

1. Открыть `README.md`.
2. Поднять проект локально.
3. Сделать 1 микрофичу:
   - добавить поле `source` у лида;
   - вывести в таблице.
4. Сделать коммит и задеплоить.
5. Повторить цикл.

Рабочее правило: не ждать идеального плана, а строить маленькими завершенными шагами.
